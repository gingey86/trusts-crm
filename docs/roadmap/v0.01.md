# v0.01: Synthetic prototype

v0.01 proves the complete fundraising workflow with fictional data. Completion requires installation on a clean Docker-capable Linux host through the documented normal setup procedure; development and ordinary testing use synthetic data only.

## Implementation sequence

1. Establish the application skeleton, environment validation, control and tenant schemas, migrations and a single-command first-run setup orchestrator with owner bootstrap. Integrate mature authentication, role policy and tenant routing before adding domain handlers. Prove isolation between two synthetic databases and keep privileged credentials outside the web runtime.
2. Implement decimal money, date-only fields, financial years and annual budget rates. Add transactional domain services, audit events and optimistic concurrency.
3. Build Funder, Contact and Interaction records, followed by Opportunities, the board/table pipeline and Tasks with designated next actions.
4. Implement Application submission and decisions, successful Grant creation, structured Obligations and completion. Preserve rejected and archived history.
5. Deliver the annual/monthly Calendar, Dashboard, Search and Settings. Calendar items must derive from records; reporting must retain native values and identify missing conversions.
6. Add private local attachment storage, CSV import, structured export and restoration. Implement archival without breaking historical links.
7. Complete the relevant automated tests and clean-host installation checks. Verify that application-container replacement preserves databases and documents.

Authentication, authorisation, tenant routing, import/export and archival are required in this milestone. Production hardening and operational readiness are assessed at v0.05.

## Completion criteria

Acceptance criteria A01–A16 must pass. A user must be able to complete Funder → Opportunity → Application → Decision → Grant → Obligation → Completion, use both principal views and manage annual budget rates through Settings.

Installation must require no source edits or undeclared host configuration. Record the actual test results and keep documentation aligned with the implemented commands. All development and acceptance data must remain synthetic.

The product exclusions remain in force. Fix lifecycle and usability defects before adding further feature classes.
