# v0.1: Pilot release

v0.1 tests the complete trusts-and-foundations workflow in controlled real-world use. The production readiness gate must pass before any charity data is accepted.

## Required product

The release includes funder relationships and history, contacts, interactions, opportunities, explicit applications and decisions, grants, structured obligations and tasks. Pipeline and the annual/monthly Calendar are the principal working views. Private documents, search, dashboard summaries and direct links between related records support the workflow.

Organisation settings include users, reporting currency, financial years and annual budgeting rates. Native amounts must remain available, with missing conversions identified in reports. CSV import, full data export, archive behaviour, authentication, roles and audit logging are required.

Management reports cover pipeline totals and stage counts, submitted applications, decided-application success rates, awards, active grants and forthcoming obligations. Date filters and conversion bases must be explicit. Award totals use Grants to avoid counting an Application and its resulting Grant twice.

## Release validation

Test a clean installation from the release artefacts, an upgrade with migration failure and recovery, and complete export/restoration into a separate self-hosted instance. Repeat all acceptance tests and verify accessible annual calendar use at realistic volume, keyboard operation and responsive phone use.

Identify the application release, image digest and migration versions. Include the project's selected open-source software licence before distributing implemented software. Document source builds until published versioned images are available.

## Pilot operation

Onboard organisations gradually. Verify settings, users, annual rates, import results and backups before routine use. Confirm processor arrangements, data location, retention, incident contacts and privileged MFA. Production data must not be copied into ordinary development or staging environments.

Evaluate whether fundraisers can carry out their normal work with little training, understand funder history and manage deadlines and obligations without maintaining parallel systems. Prioritise defects in these workflows before expanding product scope.

Maintain independent encrypted backups, restoration tests, patching, monitoring, offboarding and controlled support access. Hosted and self-hosted installations use the same supported data model and customer-exit procedures.
