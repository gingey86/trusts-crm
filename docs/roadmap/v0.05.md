# v0.05: Production readiness

v0.05 establishes whether the application is suitable for controlled use with real charity data. It builds on the complete synthetic workflow and isolation tests required for v0.01.

## Required work

Authentication must support verified email, recovery, privileged MFA, configured session expiry and revocation. Verify server-side role enforcement, CSRF protection, rate limits and secure production cookies. Complete tenant isolation across database access, private files, temporary artefacts and caches, and verify protected business audit and deployment-appropriate secure uploads. Test inspection failures where a scanner is configured; no particular scanner product is a release prerequisite.

Provisioning and migrations must be automated, versioned and safe to retry. A failed tenant setup must remain unavailable until health and schema checks pass. The application must not receive provisioning credentials or expose a platform-wide CRM browsing interface.

Demonstrate complete customer export and restoration into a separate self-hosted installation. Prove encrypted off-site backup, whole-service recovery and restoration of one organisation without affecting another. Verify organisation-controlled long-term CRM/business-audit retention, source-safe technical cleanup and reapplication of deliberate erasure after a restore. Establish managed backup/log policy before production; self-hosters choose their own recovery retention. No operational rotation may erase source CRM history because of age.

Deploy a synthetic candidate to the secured managed production environment. Verify firewall rules, private administrative access, database network restrictions, patching, monitoring and capacity. Self-hosted installations must be able to meet the same application security requirements on their own Linux infrastructure.

Before accepting real data, establish controller/processor responsibilities, data location, subprocessors, retention, deletion, user offboarding, incident response and exceptional support-access procedures. Exercise those procedures with synthetic scenarios.

## Completion criteria

Acceptance criteria A17–A21 must pass, and A01–A16 must remain valid. Installation and upgrade instructions must match the implemented commands. Record the application, image and schema versions and a verified recovery point.

Security, isolation, privacy and recovery failures block real-data use. New product feature classes are outside this milestone.
